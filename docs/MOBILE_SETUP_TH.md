# ตั้งค่าสัญญาณเข้า Telegram จากมือถือ (ไม่ต้องใช้คอม ไม่ต้องเปิด MT5)

ระบบนี้ให้ **GitHub รันการวิเคราะห์ให้ฟรี** ตามเวลาที่ตั้งไว้ แล้วส่งสัญญาณเข้า Telegram
ทุกขั้นตอนทำบนมือถือได้ ใช้เวลาประมาณ 15 นาที ตั้งครั้งเดียวจบ

```
[ GitHub รันให้ฟรีทุก 30 นาที ]         [ มือถือคุณ ]
   ดึงราคา → วิเคราะห์ SMC     ──────►   Telegram เด้งสัญญาณ
   ติดตาม TP/SL ให้ต่อเนื่อง               เปิดออเดอร์ในแอปโบรกเกอร์
```

**ไม่ต้องเปิดคอม ไม่ต้องมี VPS ไม่ต้องติดตั้ง MT5**

## ขั้นที่ 1 — สร้างบอทใน Telegram (ทีละหน้าจอ)

### 1.1 เปิดแอป Telegram แล้วค้นหา BotFather

1. เปิดแอป **Telegram** บนมือถือ
2. แตะ **ไอคอนแว่นขยาย 🔍** มุมขวาบน
3. พิมพ์: `@BotFather`
4. จะมีรายการขึ้นมาหลายตัว — **เลือกตัวที่ชื่อ "BotFather" และมีเครื่องหมายติ๊กสีฟ้า ✅ ข้างชื่อ**

> ⚠️ มีบอทปลอมชื่อคล้ายกันเยอะมาก **ต้องมีติ๊กสีฟ้าเท่านั้น** ตัวจริงมีผู้ติดตามหลักล้าน

### 1.2 กด Start

แตะปุ่ม **START** สีฟ้าด้านล่างจอ

BotFather จะตอบกลับมาเป็นข้อความยาว ๆ ประมาณนี้:
```
I can help you create and manage Telegram bots.
You can control me by sending these commands:

/newbot - create a new bot
/mybots - edit your bots
...
```

### 1.3 สั่งสร้างบอทใหม่

พิมพ์ในช่องแชท: `/newbot` แล้วกดส่ง

BotFather ตอบ:
```
Alright, a new bot. How are we going to call it?
Please choose a name for your bot.
```

### 1.4 ตั้งชื่อบอท (ชื่อที่จะแสดง)

พิมพ์ชื่ออะไรก็ได้ ภาษาไทยหรืออังกฤษก็ได้ เช่น:
```
CapitalGuard Signal
```

BotFather ตอบ:
```
Good. Now let's choose a username for your bot.
It must end in `bot`. Like this, for example:
TetrisBot or tetris_bot.
```

### 1.5 ตั้ง username (ต้องไม่ซ้ำใครทั้งโลก)

**กติกา:** ภาษาอังกฤษ ตัวเลข ขีดล่างเท่านั้น และ**ต้องลงท้ายด้วย `bot`**

พิมพ์ เช่น (ใส่เลขหรือชื่อตัวเองต่อท้ายให้ไม่ซ้ำ):
```
jetsada_signal_2026_bot
```

**ถ้าซ้ำ** BotFather จะตอบ `Sorry, this username is already taken.` → พิมพ์ชื่อใหม่ไปเรื่อย ๆ จนผ่าน

### 1.6 รับ Token ← ขั้นสำคัญที่สุด

เมื่อผ่าน BotFather จะตอบแบบนี้:
```
Done! Congratulations on your new bot.
You will find it at t.me/jetsada_signal_2026_bot

Use this token to access the HTTP API:
8123456789:AAHk3_xYzAbCdEfGhIjKlMnOpQrStUvWxYz

Keep your token secure and store it safely.
```

**บรรทัดที่เป็นตัวเลขยาว ๆ มีเครื่องหมาย `:` ตรงกลาง คือ token ของคุณ**

👉 **แตะค้างที่ข้อความ token → เลือก Copy** เก็บไว้ก่อน (จะใช้ในขั้นที่ 3)

> 💡 เก็บ token ไว้ที่ไหนดี: ส่งข้อความหาตัวเองใน Telegram (แชท "Saved Messages") จะหาเจอง่าย
> 🔒 **ห้ามส่งให้ใครเด็ดขาด** ถ้าหลุด พิมพ์ `/revoke` กับ BotFather เพื่อยกเลิกและออกใหม่

## ขั้นที่ 2 — เพิ่มบอทเข้าแชทและหา Chat ID

### 2.1 เปิดแชทกับบอทที่สร้าง

**วิธีที่ง่ายที่สุด:** ในข้อความที่ BotFather ตอบมา จะมีลิงก์ `t.me/ชื่อบอทของคุณ` → **แตะลิงก์นั้น** จะเด้งเข้าแชทบอททันที

หรือค้นหาเอง: แตะ 🔍 → พิมพ์ username ที่ตั้งไว้ (เช่น `jetsada_signal_2026_bot`)

### 2.2 กด START ← ข้ามไม่ได้เด็ดขาด

แตะปุ่ม **START** สีฟ้าด้านล่าง

จอจะยังเงียบ ๆ ไม่มีอะไรตอบกลับ — **ถูกต้องแล้ว** เพราะบอทเรายังไม่มีโค้ดตอบข้อความ
แต่การกด START คือการ**อนุญาตให้บอทส่งข้อความหาคุณได้** ซึ่งเป็นกฎของ Telegram

> ⚠️ **ถ้าไม่กด START ระบบจะส่งสัญญาณหาคุณไม่ได้เลย** และจะขึ้น error 400 ใน log

### 2.3 หา Chat ID ของคุณ

Chat ID คือเลขประจำตัวบัญชี Telegram ของคุณ ใช้บอกระบบว่าจะส่งสัญญาณไปหาใคร

1. แตะ 🔍 → พิมพ์: `@userinfobot`
2. เลือกบอทชื่อ **userinfobot**
3. แตะ **START**
4. บอทจะตอบกลับมาทันที:
```
Id: 123456789
First: Jetsada
Lang: th
```

👉 **เลขหลัง `Id:` คือ Chat ID ของคุณ** — แตะค้างเพื่อคัดลอกเก็บไว้

## ขั้นที่ 7 — ตั้ง cron ภายนอกให้รันทุก 5 นาทีจริง ⚠️ สำคัญ

### ทำไมต้องมี

ในไฟล์ workflow ตั้ง `*/5` (ทุก 5 นาที) ไว้ แต่ **GitHub ไม่ทำตามจริง** — schedule ของ GitHub เป็นแบบ *best-effort* และถูก throttle หนักมากใน repo สาธารณะ ตัวเลขที่วัดได้จริงจาก repo นี้:

| เวลาที่รันจริง | ห่างจากรอบก่อน |
|---|---|
| 13:26 | — |
| 19:09 | **3 ชม. 43 นาที** |
| 22:39 | **3 ชม. 30 นาที** |

ได้ราว **6 รอบ/วัน** แทนที่จะเป็น 288 รอบ — โอกาสจับสัญญาณ 7–10 ไม้/วันแทบเป็นศูนย์ วิธีแก้คือให้บริการภายนอกยิงเข้ามาแทน

### 7.1 สร้าง GitHub Token

1. ไปที่ **github.com** → รูปโปรไฟล์ → **Settings** (ของบัญชี ไม่ใช่ของ repo)
2. เลื่อนลงล่างสุด → **Developer settings**
3. **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
4. กรอก:
   - **Token name:** `signal-bot-cron`
   - **Expiration:** เลือกให้นานที่สุด (เช่น 1 ปี หรือ No expiration)
   - **Repository access:** **Only select repositories** → เลือก `trade`
5. **Permissions** → **Repository permissions** → หา **Actions** → เปลี่ยนเป็น **Read and write**
   *(ตัวอื่นไม่ต้องแตะ ยิ่งให้สิทธิ์น้อยยิ่งปลอดภัย)*
6. กด **Generate token** → **คัดลอกเก็บไว้ทันที** (ปิดหน้าแล้วดูซ้ำไม่ได้)

### 7.2 ตั้ง cron ที่ cron-job.org

1. เปิด **cron-job.org** → **Sign up** (ฟรี)
2. ยืนยันอีเมล → กด **Create cronjob**
3. กรอกตามนี้:

| ช่อง | ค่าที่ใส่ |
|---|---|
| **Title** | `CapitalGuard Signal Bot` |
| **URL** | `https://api.github.com/repos/jetsadachansang-byte/trade/actions/workflows/signal-bot.yml/dispatches` |
| **Schedule** | Every **5** minutes |

4. เปิดแท็บ **Advanced** แล้วตั้ง:
   - **Request method:** `POST`
   - **Request body:**
     ```
     {"ref":"main"}
     ```
   - **Headers** — เพิ่มทีละบรรทัด:

     | Key | Value |
     |---|---|
     | `Accept` | `application/vnd.github+json` |
     | `Authorization` | `Bearer ` แล้วตามด้วย token จากขั้น 7.1 |
     | `X-GitHub-Api-Version` | `2022-11-28` |
     | `Content-Type` | `application/json` |

5. กด **Create**

### 7.3 ตรวจว่าใช้ได้

- ที่ cron-job.org กด **Run now** แล้วดูช่อง status → ต้องขึ้น **204** (ไม่ใช่ 401 หรือ 404)
- กลับมาที่ GitHub แท็บ **Actions** → ต้องมี run ใหม่โผล่ขึ้นมาภายในไม่กี่วินาที

| ผลที่ได้ | แปลว่า |
|---|---|
| **204** | ✅ สำเร็จ (GitHub ตอบ 204 แปลว่ารับคำสั่งแล้ว ไม่มีเนื้อหาตอบกลับ) |
| **401** | token ผิด หรือลืมคำว่า `Bearer ` นำหน้า |
| **404** | ชื่อ repo ผิด หรือ token ไม่ได้ให้สิทธิ์ repo นี้ |
| **403** | token ไม่มีสิทธิ์ **Actions: Read and write** |

> **ไม่ต้องส่ง inputs** — ค่า default ในไฟล์ workflow ตั้งเป็น `false` ทั้งหมดแล้ว รอบที่ cron ยิงมาจึงทำงานเหมือนรอบปกติ ไม่สแปมรายงานภาพรวม
>
> **schedule เดิมยังอยู่** เป็นตัวสำรองเผื่อ cron ภายนอกล่ม จะรันซ้อนกันก็ไม่เป็นไร เพราะมีตัวกันสัญญาณซ้ำต่อแท่งเทียนอยู่แล้ว
>
> **โควตา Actions:** repo นี้เป็น public จึงใช้ได้ไม่จำกัดนาที

## เป้าหมายสัญญาณต่อวัน (ปรับเกณฑ์อัตโนมัติ)

ระบบตั้งเป้า **14 สัญญาณ/วัน** จาก 14 สินทรัพย์ โดยใช้วิธี **ผ่อนเกณฑ์คะแนนตามความคืบหน้าของวัน**

### แบ่งโควตา: ทองเป็นหลัก

| กลุ่ม | เป้าหมาย/วัน | Variable |
|---|---|---|
| 🥇 **XAUUSD** | **5** (ได้มากกว่านี้ไม่จำกัด) | `GOLD_DAILY_TARGET` |
| 💱 คู่เงินที่เหลือ | 9 | ส่วนต่างจาก `DAILY_SIGNAL_TARGET` |

**สองกลุ่มนี้นับแยกกันคนละถัง** — วันที่คู่เงินนิ่ง เกณฑ์ของคู่เงินจะผ่อนลงเองโดย**ไม่ไปดึงเกณฑ์ของทองให้หย่อนตาม** และถ้าทองมีจังหวะดีเกิน 4 ไม้ ระบบส่งเพิ่มให้ ไม่มีเพดาน

### ให้น้ำหนักสายเก็บสั้น

เวลาผ่อนเกณฑ์ ระบบผ่อนให้แต่ละสไตล์ไม่เท่ากัน (`pace_weight`) — สายเดย์เทรด/สั้นรับภาระโควตารายวัน ส่วนไม้ถือยาวแทบไม่ผ่อนเลย เพราะ**ไม้ที่ถือข้ามวันไม่ควรเปิดเพียงเพื่อให้ครบโควตา**

| สไตล์ | ผ่อนได้ | เกณฑ์เต็ม → เกณฑ์ต่ำสุด |
|---|---|---|
| 📊 Day Trade | 100% | 90 → 66 |
| ⚡ Scalping | 100% | 75 → 66 |
| 🔥 Scalp M1 | 80% | 72 → 67 |
| 🚀 Run Trend | **30%** | 88 → **81** |

ตัวอย่างจริง (ทอง ยังไม่ได้สัญญาณเลยทั้งวัน):

| เวลา | ตามหลังเป้า | Day | Scalp | Run Trend |
|---|---|---|---|---|
| 06:00 | 25% | 84 | 73 | 86 |
| 10:00 | 42% | 80 | 71 | 85 |
| 14:00 | 58% | 76 | 70 | 84 |
| 18:00 | 75% | 72 | 68 | 83 |
| 22:00 | 92% | 68 | 67 | 82 |

พอส่งครบตามจังหวะแล้ว เกณฑ์**เด้งกลับเป็นค่าเต็มทันที**

**ผ่อนได้แค่คะแนน ไม่ผ่อนเงื่อนไขโครงสร้าง** — ทุกสัญญาณยังต้องผ่าน SMC pipeline ครบ 11 ขั้น (BOS, Order Block, Sweep ฯลฯ) และ**ไม่มีวันต่ำกว่าพื้น 66 คะแนน**

### เกรดคุณภาพ S / A / B / C / D — ติดมากับทุกสัญญาณ

| เกรด | คะแนน | คำแนะนำขนาดไม้ |
|---|---|---|
| 🏆 **S** | ≥ 92 | ขนาดปกติได้เต็มที่ |
| **A** | 85–91 | ขนาดปกติ |
| **B** | 78–84 | **ลดเหลือ 50–70%** |
| **C** | 72–77 | **ลดเหลือ 30–50%** |
| **D** | < 72 | **ลดเหลือ 20–30% หรือข้ามไม้นี้ก็ได้** |

ข้อความจะแสดงชัด:
```
⭐ Confidence Score: 82%  · เกรด B
💰 คุณภาพปานกลาง — ลดขนาดไม้เหลือ 50-70%
```
และเกรด B/C/D จะขึ้นในรายการความเสี่ยงว่า *"ผ่านเกณฑ์ที่ผ่อนลงเพื่อให้ครบเป้าหมายรายวัน ไม่ใช่ setup ระดับ S/A"*

> **วันไหนมีแค่เกรดไหนก็ได้เกรดนั้น** — ระบบไม่ปั้นเกรดให้ครบทุกตัวอักษร ถ้าตลาดดีทั้งวันก็อาจได้ S/A ล้วน ถ้าตลาดฝืดก็อาจเป็น C/D เป็นส่วนใหญ่ เกรดคือ**ผลของคะแนนจริง** ไม่ใช่โควตา

### ⚠️ ไม่ใช่การรับประกัน

## การวิเคราะห์ข่าวเศรษฐกิจ

ระบบดึง **ปฏิทินข่าวจริงจาก Forex Factory** ทุกรอบสแกน (ฟรี ไม่ต้องสมัคร) แล้วใช้ 3 ทาง:

**1. กรองไม่ให้เทรดช่วงข่าว** — เจอข่าว impact สูงของสกุลที่เกี่ยวข้อง ±45 นาที → หยุดสแกนทั้งรอบ

**2. ให้คะแนน (น้ำหนัก 5%)**
| สถานการณ์ | คะแนนข่าว |
|---|---|
| ไม่มีข่าวแรงใกล้ ๆ | 100 |
| มีข่าวใน 1–2 ชม. | 65 |
| มีข่าวใน 1 ชม. | 40 |
| อยู่ในช่วง blackout | 0 (ไม่ส่งอยู่แล้ว) |
| **ดึงข่าวไม่ได้** | **50 (เป็นกลาง)** |

**3. ประเมินทิศทางจากตัวเลขที่ประกาศแล้วเท่านั้น**
เทียบ `actual` กับ `forecast` ของข่าวที่ออกแล้วใน 12 ชม. เช่น
- CPI สูงกว่าคาด → USD แข็ง → **กดดันทอง**
- Unemployment สูงกว่าคาด → USD อ่อน → **หนุนทอง**
- ข่าวที่ยังไม่ประกาศ หรือระบบไม่รู้จัก → **ไม่ตัดสิน**

### แหล่งราคาทอง

**ทองใช้ราคา spot เท่านั้น** และ **ต้องมี Twelve Data API key** เพราะ Yahoo ไม่มีราคาทอง spot ให้ (`XAUUSD=X` และ `XAU=X` คืน HTTP 404 ทั้งคู่ — ยืนยันจาก log จริง)

### ⚠️ ต้องทำ: สมัคร Twelve Data ฟรี (ไม่งั้นทองจะไม่มีสัญญาณเลย)

ทำในมือถือได้ ใช้เวลาไม่ถึง 3 นาที:

1. เปิด **twelvedata.com** → กด **Sign Up** (ใช้อีเมลหรือ Google)
2. ยืนยันอีเมล → เข้าหน้า **Dashboard** → หัวข้อ **API Key**
3. กดคัดลอก key (หน้าตาเป็นตัวอักษร+ตัวเลขยาว ๆ)
4. กลับมาที่ repo → **Settings → Secrets and variables → Actions**
5. กด **New repository secret**
   - Name: `TWELVEDATA_API_KEY`
   - Secret: วาง key ที่คัดลอกมา
6. กด **Add secret** เสร็จแล้ว

ถ้ายังไม่ได้ใส่ key log จะขึ้นเตือนทุกรอบว่า
`gold: no TWELVEDATA_API_KEY - Yahoo has no spot gold, so gold will be skipped`

Twelve Data แผนฟรีให้ **800 คำขอ/วัน** ส่วนทองต้องใช้ 8 ชุดข้อมูลต่อการสแกนหนึ่งครั้ง (M1/M5/M15/M30/H1/H4/D1/W1)

| ความถี่ทอง | คำขอ/วัน | โควตา 800 |
|---|---|---|
| ทุก 5 นาที | 2,304 | ❌ เกิน |
| ทุก 10 นาที | 1,152 | ❌ เกิน |
| **ทุก 15 นาที** | **768** | ✅ **ค่าเริ่มต้น** |

**คู่เงินไม่ได้รับผลกระทบ** — ยังใช้ Yahoo ฟรี สแกนทุก 5 นาทีเหมือนเดิม สายเก็บสั้นของคู่เงินจึงไม่ช้าลง

ปรับได้ด้วย Variable `GOLD_SCAN_MINUTES` (ถ้า log ขึ้นว่าโควตาเต็ม ให้เพิ่มเป็น `20`)

### เช็คว่าได้ราคาจากไหน

ทุกรอบจะพิมพ์บรรทัดนี้ใน log ของ Actions:
```
price source: EURUSD=EURUSD=X XAUUSD=XAUUSD=X
```
ถ้ามีคำว่า `[PROXY]` ต่อท้ายตัวไหน แปลว่าตัวนั้นไม่ใช่ spot

**ถ้าอยากยอมใช้ futures แทนที่จะไม่มีทองเลย** ตั้ง Variable `ALLOW_GOLD_FUTURES` = `true` ระบบจะตกไปใช้ `GC=F` ได้ และจะขึ้นคำเตือน *"ราคา COMEX futures ไม่ใช่ spot — อาจต่างจากกระดาน 2-10 จุด"* ทั้งในสัญญาณและรายงานภาพรวมทุกครั้ง (ค่าเริ่มต้นคือ `false`)

### 🚫 ระบบไม่แต่งข่าวเด็ดขาด

ถ้าดึงปฏิทินไม่ได้ (เน็ตล่ม / ฟีดล่ม) ระบบจะ:

- **ไม่ใช้ข่าวเป็นเหตุผลสนับสนุนสัญญาณ**
- เพิ่มเข้าไปในรายการความเสี่ยงของสัญญาณนั้น

## 4 สไตล์การเทรดในระบบเดียว

ระบบวิเคราะห์ทุกสินทรัพย์ด้วย **4 สไตล์พร้อมกัน** แต่ละสไตล์ใช้ timeframe และเป้าหมายต่างกัน จึงมีสัญญาณเข้ามาบ่อยขึ้นมาก

| สไตล์ | ส่วน | เข้าที่ | โครงสร้างที่ดู | TP (R) | คะแนนขั้นต่ำ | หมดอายุ |
|---|---|---|---|---|---|---|
| 🔥 **Scalp M1** | เก็บสั้น | M1 | M30/M15/M5 | 0.5 / 1 / 1.5 | 72 | 2 ชม. |
| ⚡ **Scalping** | เก็บสั้น | M5 | H1/M30/M15 | 0.5 / 1 / 1.5 | 75 | 4 ชม. |
| 📊 **Day Trade** | เก็บสั้น | M15 | D1/H4/H1 | 1 / 2 / 3 | 90 | 12 ชม. |
| 🚀 **Run Trend** | **ถือยาว** | H1 | W1/D1/H4 | 2 / 4 / 6 | 88 | 72 ชม. |

**สไตล์เร็วผ่อนเงื่อนไขลง** เพราะกราฟ M1/M5 แทบไม่มีทางเกิด FVG + Mitigation + โครงสร้าง H4 ตรงกันพร้อมกัน — ถ้าใช้เกณฑ์เดียวกับ Day Trade จะไม่มีสัญญาณเลย

**แต่ละสไตล์แยกกันอิสระ** — XAUUSD มีสัญญาณ Scalp กับ Run Trend พร้อมกันได้ ไม่บล็อกกัน

### สายเก็บสั้น กับ สายถือยาว แจ้งแยกคนละส่วน

ทุกรอบสแกน ระบบจะจัดสัญญาณเป็น **2 ส่วน** และขึ้นหัวข้อคั่นก่อนเสมอ (เรียงเกรดดีสุดขึ้นก่อนในแต่ละส่วน):

```
⚡ สัญญาณสายเก็บสั้น / Day Trade
3 สัญญาณ · ปิดภายในวัน
ตั้ง SL/TP ทันทีที่เข้า และเลื่อน SL เป็น BE เมื่อถึง TP1
━━━━━━━━━━━━━━
  → 📊 Day Trade · TF M15   (XAUUSD, เกรด S)
  → ⚡ Scalping · TF M5      (XAUUSD, เกรด B)
  → 📊 Day Trade · TF M15   (EURUSD, เกรด D)

🚀 สัญญาณสายถือยาว / Run Trend
1 สัญญาณ · ถือข้ามวันถึงสัปดาห์
แยกส่วนจากไม้สั้น — ปิดบางส่วนที่ TP1 แล้วปล่อยที่เหลือวิ่ง
━━━━━━━━━━━━━━
  → 🚀 Run Trend · TF H1     (XAUUSD, เกรด A)
```

ตัวสัญญาณเองก็ติดป้ายกำกับซ้ำอีกชั้น เผื่อกดอ่านข้อความเดี่ยว ๆ หรือ forward ต่อ:
```
🚀 Run Trend · TF H1
🚀 สายถือยาว (Run Trend)
📊 สินทรัพย์: XAUUSD
📈 ประเภท: BUY
...
```

**ทำไมต้องแยก** — ไม้ถือยาวที่ถูกจัดการแบบไม้สั้น (ปิดหมดที่ TP1) จะไม่ใช่ไม้ถือยาวอีกต่อไป ทั้งขนาดไม้ ระยะ SL และวิธีปิดต่างกันคนละแบบ จึงต้องไม่ปนกันในสายตา

รายงานภาพรวมทุก 15 นาทีก็แยกหัวข้อเหมือนกัน โดยมีทองขึ้นก่อนเสมอ

**เลือกเฉพาะสไตล์ที่อยากได้:** ตั้ง Variable `PROFILES`
- `turbo,scalp,day,trend` = ทั้งหมด (ค่าเริ่มต้น)
- `scalp,day` = เอาแค่สายสั้นกับเดย์เทรด
- `day` = เอาแค่เดย์เทรดอย่างเดียว

> ⚠️ **Scalp M1 มีข้อจำกัดจริง** — ระบบสแกนทุก 5 นาที แต่แท่ง M1 เกิดทุกนาที กว่าสัญญาณจะถึงมือคุณราคาอาจวิ่งไปแล้ว 2–5 แท่ง **ให้ยึด Entry Zone เป็นหลัก ถ้าราคาหลุดโซนไปแล้วอย่าไล่**
> ถ้าไม่ชอบให้เอาออกจาก `PROFILES` ได้

## ข้อมูลราคาแม่นแค่ไหน

ค่าเริ่มต้นใช้ **Yahoo Finance ฟรี ไม่ต้องสมัคร** — ทองใช้ราคา futures (GC=F) ซึ่งวิ่งตามราคา spot ใกล้เคียงมาก แต่ **ตัวเลขจะต่างจากโบรกเกอร์ของคุณเล็กน้อย**

ถ้าอยากได้ข้อมูลแม่นและเสถียรกว่า (แนะนำ):
1. สมัครฟรีที่ [twelvedata.com](https://twelvedata.com) (ใช้มือถือได้ ใช้อีเมลอย่างเดียว)
2. คัดลอก API key
3. เพิ่มเป็น Secret ชื่อ `TWELVEDATA_API_KEY`
4. เพิ่ม Variable `REQUEST_PAUSE` = `8` (แผนฟรีจำกัด 8 request/นาที)

ระบบจะใช้ Twelve Data ก่อน ถ้าล้มจะสลับไป Yahoo ให้อัตโนมัติ

> ⚠️ **ราคาที่ใช้วิเคราะห์ต่างจากโบรกเกอร์เล็กน้อยเสมอ** — ใช้ระดับ SL/TP ในสัญญาณเป็นแนวทาง
> แล้วปรับตามราคาจริงในแอปโบรกเกอร์ของคุณ

### ราคาไม่ตรงกระดาน / ไม่ปัจจุบัน?

ทุกรายงานจะบอก**อายุของข้อมูล**ให้เห็นชัด:
- `ข้อมูลอัปเดตเมื่อ 3 นาทีที่แล้ว` = ปกติ
- `⚠️ ข้อมูลช้า 45 นาที — ราคาอาจไม่ตรงกระดาน` = ฟีดหยุดอัปเดต ให้ระวัง

**สาเหตุที่ราคาต่างจาก TradingView:**
1. **ฟีดฟรีมีดีเลย์** ราว 1–15 นาที (TradingView เสียเงินถึงจะได้ real-time)
2. **โบรกเกอร์แต่ละเจ้าราคาไม่เท่ากัน** ต่างกัน 0.1–0.5 จุดเป็นเรื่องปกติ
3. เดิมระบบใช้ **ทองฟิวเจอร์ส** ซึ่งต่างจาก spot หลายดอลลาร์ — แก้เป็นราคา spot แล้ว

**อยากได้ใกล้เคียง real-time ที่สุด:** สมัคร Twelve Data ฟรี (ดูด้านบน) ดีเลย์น้อยกว่าและเสถียรกว่า Yahoo มาก

## เปิดออเดอร์บนมือถือเมื่อได้สัญญาณ

**1. คำนวณ lot ตามความเสี่ยงของคุณ** (ระบบไม่คำนวณให้ เพราะไม่รู้ขนาดพอร์ต)
```
Lot = (เงินทุน × %ความเสี่ยง) ÷ (ระยะ SL เป็นจุด × มูลค่าต่อจุด)
```
ตัวอย่าง: ทุน $1,000 · เสี่ยง 1% = $10 · SL ห่าง 670 จุด (ทอง 0.01 lot ≈ $0.10/จุด)
→ lot ≈ **0.15**

**2. เปิดแอปโบรกเกอร์ (MT5/MT4 มือถือ)** → เลือก symbol → **New Order**
- Volume = lot ที่คำนวณได้
- **Stop Loss = ใส่ทุกครั้ง** ← ห้ามข้ามเด็ดขาด
- Take Profit = TP1 (หรือ TP2 ถ้าอยากถือยาว)

**3. เมื่อได้ ✅ TP1 Hit** → ปิดครึ่งหนึ่ง + เลื่อน SL มาที่ราคาเข้า (Break Even)

**4. เมื่อได้ ❌ Signal Cancelled** → ยังไม่เข้า = ไม่ต้องเข้า / เข้าแล้ว = พิจารณาปิดก่อนโดน SL

## ข้อจำกัดที่ต้องรู้จริง ๆ

1. **โควตา GitHub Actions ← เรื่องสำคัญที่สุด**

   | ความถี่ | รอบ/เดือน | นาที/เดือน | repo ส่วนตัว (ฟรี 2,000 น.) |
   |---|---|---|---|
   | ทุก 5 นาที (ปัจจุบัน) | ~6,300 | ~6,300 | ❌ **เกิน 3 เท่า** หมดราววันที่ 10 |
   | ทุก 15 นาที | ~2,100 | ~2,100 | ⚠️ เกินนิดหน่อย |
   | ทุก 30 นาที | ~1,050 | ~1,050 | ✅ พอดี |

   GitHub คิดเงินเป็น**นาที ปัดขึ้น** ต่อ 1 รอบ แม้รอบจะใช้จริงแค่ 25 วินาที

   **ทางแก้ 2 ทาง:**
   - **เปลี่ยน repo เป็น Public** → รันฟรีไม่จำกัด (Settings → เลื่อนล่างสุด → Change visibility)
     token ยังปลอดภัยเพราะเก็บใน Secrets ไม่ได้อยู่ในโค้ด แต่คนอื่นจะเห็นตรรกะการเทรดของคุณ
   - **หรือคงเป็น Private แล้วลดความถี่** เป็นทุก 30 นาที (แก้บรรทัด `cron` ใน `.github/workflows/signal-bot.yml`)

2. **เวลารันไม่เป๊ะ** — GitHub cron อาจช้ากว่าเวลาที่ตั้ง 5–15 นาทีในช่วงที่คนใช้เยอะ ไม่เหมาะกับ scalping ที่ต้องการความเร็ววินาที

3. **สแกนทุก 5 นาที** — ถี่พอสำหรับ entry M15 (สแกน 3 รอบต่อ 1 แท่ง) แต่ราคาจริงตอนเข้ายังต่างจากในสัญญาณเล็กน้อย **ให้ดูโซน Entry Zone เป็นหลัก อย่าไล่ราคา**

4. **GitHub ปิด schedule อัตโนมัติ** ถ้า repo ไม่มีความเคลื่อนไหว 60 วัน — แต่บอทตัวนี้ commit สถานะกลับทุกครั้งที่มีสัญญาณ จึงนับเป็นความเคลื่อนไหว ปกติจะไม่โดนปิด (ถ้าเงียบนานมากให้เข้าไปกด Run workflow สักครั้ง)

5. **ราคาไม่ตรงโบรกเกอร์เป๊ะ** — ต่างกันเล็กน้อยเสมอ ใช้เป็นแนวทาง ไม่ใช่ตัวเลขตายตัว

6. **ไม่รับประกันผลกำไร** — สัญญาณคือความน่าจะเป็น ควรทดลองดูเฉย ๆ 2–4 สัปดาห์ก่อนใช้เงินจริง
